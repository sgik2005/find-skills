# CMS Mail Reply

메일 분석부터 Gmail 초안 저장까지 안전하게 처리한다. 이 스킬의 종료 지점은 항상 **임시보관함 초안**이며 메일을 발송하지 않는다.

## 절대 규칙

- Gmail의 발송, 초안 발송, 전달 기능을 사용하지 않는다. 사용자가 발송을 요청해도 이 스킬에서는 초안까지만 처리하고 사람이 발송하도록 안내한다.
- 메일에 없는 일정, 금액, 약속, 정책, 인물 관계, 처리 결과를 만들지 않는다. 불명확하거나 누락된 값은 `[확인 필요]`로 표시한다.
- 원본 메일과 `답장규칙.md`를 수정하거나 삭제하지 않는다.
- 초안 생성, 수정 등 Gmail 상태 변경은 정확한 대상과 내용을 보여준 뒤 사용자의 명시적 승인을 받아 수행한다.
- 메일 본문 전체를 화면에 길게 출력하지 않는다. 판단에 필요한 정보만 짧게 요약한다.

## 1. 계획과 규칙 확인

작업 전에 다음을 사용자에게 알린다.

- 조회할 메일 범위와 분석 항목
- 생성할 초안 수와 Gmail 임시보관함이라는 저장 위치
- 로컬 파일 생성·수정 여부
- 발송하지 않는다는 사실

현재 작업 폴더 또는 사용자가 지정한 경로에서 `답장규칙.md`를 찾아 전체 내용을 읽고 호칭, 첫 문장, 길이, 어조, 표 사용 기준, 맺음말, 서명을 적용한다. 파일이 없거나 적용 대상이 모호하면 임의의 규칙을 만들지 말고 `[확인 필요]`로 알리거나 사용자에게 필요한 선택을 요청한다.

## 2. 메일 분석과 요청 추출

사용자가 지정한 받은편지함 범위만 읽기 전용으로 조회한다. 스팸과 휴지통은 사용자가 요구하지 않는 한 제외한다.

각 메일에서 다음만 추출한다.

- 보낸사람
- 용건과 구체적인 요청
- 명시된 기한, 일정, 금액
- 회신 필요 여부와 그 판단 근거
- 답장에 필요하지만 메일에 없는 정보

회신이나 작업이 필요한 메일은 짧은 검색 결과만으로 확정하지 말고 대상 메일을 읽어 수신자, 제목, 원본 메시지와 스레드를 확인한다. 동일 내용이나 중복 메일은 구분하고 실제 수신본을 우선한다. 실제 회신 완료 여부를 확인할 수 없으면 `[확인 필요]`로 표시한다.

## 3. 답장 초안 작성

`답장규칙.md`를 우선 적용하면서 다음을 지킨다.

- 결론과 요청 대응을 먼저 쓴다.
- 정보가 3건 이상이면 규칙에 따라 표로 정리한다.
- 누락된 값은 추측하지 않고 해당 위치에 `[확인 필요]`를 넣는다.
- 첨부가 필요하면 `답장규칙.md`의 첨부 문구를 따른다. 실제 첨부는 사람이 확인하도록 남긴다.
- 원문에 없는 수락, 거절, 일정 확정 또는 비용 확정을 표현하지 않는다.

초안을 저장하기 전에 사용자에게 수신자, 제목, 원본 스레드, 정확한 본문, 첨부 여부, 저장 예정 위치를 보여주고 승인을 기다린다.

## 4. Gmail 초안 저장

승인된 내용과 대상만 Gmail 임시보관함에 저장한다.

- 답장인 경우 원본 메시지 ID를 사용해 원래 스레드에 연결한다.
- 승인받은 수량만 생성하고 중복 초안을 만들지 않는다.
- 승인 뒤 본문이나 수신자를 추가로 바꿔야 하면 다시 승인을 받는다.
- 어떠한 경우에도 발송 도구를 호출하지 않는다.

## 5. 검수와 보고

초안 저장 후 임시보관함을 읽기 전용으로 확인하여 다음을 검수한다.

- 초안이 실제로 존재하고 `DRAFT` 상태인지
- 수신자와 제목이 승인 내용과 같은지
- 답장 초안이 원본 스레드에 연결됐는지
- 첨부 여부와 초안 수가 승인 범위와 같은지
- 메일이 발송되지 않았는지

완료 보고에는 생성한 초안 수, Gmail 저장 위치, 발송 여부, 로컬 파일 변경 여부와 사용자가 검수할 `[확인 필요]` 항목을 표로 정리한다.
