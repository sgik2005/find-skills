# PPTX 제작 절차와 판단 기준

## 1. 입력 자료 확인

1. 프로젝트 지침과 대상 폴더의 연결 상태를 읽기 전용으로 확인한다.
2. 사용자가 지정한 자료만 읽고, 파일별 역할을 `내용 근거`, `구조·아웃라인`, `디자인 규칙`, `참고용`으로 구분한다.
3. 대상 자료와 주제는 매 요청에서 받은 입력값으로 유지한다. 스킬 내부의 예시 주제나 이전 작업의 파일명을 가져오지 않는다.
4. 원자료의 해시나 수정 시각을 기록할 수 있으면 기록해 제작 후 변경 여부를 비교한다.
5. 디자인 문서가 웹 검색을 금지하거나 특정 파일만 사용하라고 하면 그 범위를 지킨다.

## 2. 승인 전 제작 계획

최종 파일을 쓰기 전에 다음 내용을 사용자에게 보여준다.

- 읽을 자료와 제외할 자료
- 최종 저장 위치, 파일명, 새 파일 여부
- 예상 슬라이드 수와 전체 흐름
- 슬라이드별 메시지 구성 원칙
- 화면 비율과 디자인 문서의 색상·간격·구성 변환안
- 요청 글꼴의 설치 여부와 대체가 필요한 경우의 후보
- 정량 차트, 표, 흐름도 등 시각화 계획과 편집 가능 방식
- 발표자 노트의 구조
- `확인 필요` 항목과 검수 계획

승인 전에는 PPTX를 생성하지 않는다. 대상 경로에 같은 이름의 파일이 있으면 덮어쓰지 말고 새 버전명 또는 명시적 승인을 요청한다.

## 3. 디자인 규칙 변환

- 사용자가 지정하지 않으면 16:9를 기본 제안하되 계획에서 명시한다.
- 웹용 px·CSS 값은 슬라이드 전체 크기에 대한 상대 비율, 여백 체계, 시각적 위계로 변환한다. px를 pt와 동일시하지 않는다.
- 색상은 문서에 적힌 HEX·RGB 값을 우선 사용한다. 그림자, 둥근 모서리, 그라데이션 등은 문서에 없으면 임의로 추가하지 않는다.
- 제목과 본문 크기는 사용자 기준을 우선한다. 기준이 없으면 제목 28pt 이상, 본문 18pt 이상을 기본안으로 제시하고 승인받는다.
- 한 슬라이드에 핵심 메시지 하나를 유지하고, 모든 요소를 안전 여백 안에 배치한다.
- 그대로 변환하면 가독성이나 편집성이 손상되는 규칙은 `확인 필요`로 표시한다.

## 4. 글꼴 판단

1. 요청 글꼴이 제작 환경에 실제 설치되어 있는지 확인한다.
2. 설치되지 않았으면 임의의 대체 글꼴을 적용한 뒤 원래 글꼴을 썼다고 보고하지 않는다.
3. 한국어 지원 여부, 굵기 범위, 가독성을 기준으로 대체 후보를 제시하고 승인을 받는다.
4. 렌더링 환경과 사용자의 재생 환경이 다르면 다른 컴퓨터에서 대체 표시될 수 있음을 `확인 필요`로 남긴다.

## 5. 콘텐츠와 시각화 제작

- 원자료에서 확인되는 사실만 사용하고, 표현을 단순화하더라도 의미를 확장하지 않는다.
- 아웃라인이 있으면 도입 → 핵심 개념 → 예시 → 활동 → 정리처럼 사용자가 정한 흐름을 유지한다.
- 표, 비교판, 흐름도, 활동 카드와 연결선은 PowerPoint에서 선택·수정 가능한 객체로 만든다.
- 정량 차트는 원자료에 수치와 단위, 비교 기준이 있을 때만 만든다. 수치 근거가 없으면 숫자를 발명하지 말고 편집 가능한 개념도·비교 도형을 사용하며 이 판단을 계획과 완료 보고에 적는다.
- 외부 이미지가 필요하면 사용자가 허용한 출처 범위 안에서만 사용하고 출처를 기록한다. 외부 검색이 금지되면 기본 도형이나 제공 자산으로 해결한다.

## 6. 발표자 노트

사용자가 별도 형식을 지정하지 않은 경우 각 슬라이드 노트는 다음 세 항목만 둔다.

1. `발표 스크립트`: 슬라이드 문장을 그대로 복사하지 않은 3~5문장
2. `교사 발문`: 1~2개
3. `[Sources]`: 해당 슬라이드 근거의 파일 경로·쪽수·출처, 없으면 `해당 없음`

항목을 추가하지 않는다. 쪽수를 특정할 수 없으면 임의로 만들지 말고 `확인 필요`로 표시한다.

## 7. 제작 후 검수와 수정

1. 저장한 PPTX를 다시 열어 슬라이드 수, 화면 비율, 노트 수, 글꼴 정보를 검사한다.
2. 모든 슬라이드를 이미지로 렌더링하고 전체 보기와 개별 슬라이드 보기를 모두 확인한다.
3. 잘림, 겹침, 글자 넘침, 낮은 대비, 부자연스러운 줄바꿈, 연결선 오류를 수정한다.
4. 편집 가능한 객체가 이미지로 납작해지지 않았는지 점검한다.
5. 원자료가 변경되지 않았는지 해시나 수정 시각으로 확인한다.
6. 검수를 통과한 최종 파일만 지정 폴더에 남기고, 자신이 만든 임시 검수 파일은 안전하게 정리한다.

오류를 수정하기 위해 같은 승인 범위에서 재생성할 수 있다. 그러나 내용 범위, 외부 자료 사용, 글꼴 대체 또는 저장 대상을 바꾸려면 다시 승인받는다.
